## 2026 Incidents

### 2026-10-27 - Anthropic: An Unreleased Internal Model Built Working Exploit Chains for Chrome, Safari, Android, Windows, and Linux

- **Target:** Chrome on macOS, Safari, Google Pixel 9 (Android), the Windows kernel QUIC stack, and Linux kernel multipath TCP
- **Impact:** Anthropic's Frontier Red Team reported that an unreleased internal research model, after initial human prompting, found the flaws and built five chains. Chrome: one-click code execution outside the sandbox, chaining a V8 heap corruption, a V8 sandbox escape, a CacheStorage race, and a FedCM use-after-free. Google assigned 62 CVEs from the work, all critical or high, including 13 sandbox escapes, fixed in Chrome 156. Safari: a one-click data-only chain that disables the same-origin policy so any site can read other signed-in sites' data. Android: photos copied from a locked Pixel 9 over USB. Windows: a remote crash of machines serving HTTP/3 (CVE-2026-33096). Linux: zero-click root over the network through a multipath TCP use-after-free (CVE-2026-98432), with about 48 minutes to leak a kernel pointer and about five more to reach a root shell. All were disclosed to vendors first and are reported patched. The Hacker News could not match some of the linked CVE records to Anthropic's descriptions
- **Root Cause:** Frontier models can now find memory-safety bugs in hardened codebases and chain them into working exploits with little human involvement, compressing the time between discovery and weaponization
- **CVE:** CVE-2026-33096, CVE-2026-98432
- **Sources:** [Anthropic](https://www.anthropic.com/research/discovering-vulnerabilities-with-claude), [The Hacker News](https://thehackernews.com/2026/10/anthropics-unreleased-ai-model-chains.html)

### 2026-10-27 - Autonomous "Cipher" Agent Finds Four Flaws in EPICS Particle-Accelerator Control Software in Under Four Hours (CVE-2026-114595)

- **Target:** EPICS Base 7.0.10 and earlier, an open-source SCADA toolkit used at about 90 scientific and industrial facilities, including Argonne's Advanced Photon Source and ITER's fusion reactor controls
- **Impact:** Causal Security's Cipher agent found and validated four previously unknown flaws in 3 hours and 49 minutes, with one human instruction authorizing deeper exploitability testing. CVE-2026-114595 (CVSS 9.8) is an integer overflow giving an attacker-controlled heap write and possible remote code execution; CVE-2026-114596 (8.2) is an out-of-bounds write that crashes controller processes; CVE-2026-114597 and CVE-2026-114598 (7.5 each) allow out-of-bounds reads and denial of service. CISA published advisory ICSA-26-300-01 on October 27, 2026. Fixed in EPICS Base 7.0.11. Exploitation requires reaching EPICS services on the control network
- **Root Cause:** Memory-unsafe network protocol parsing in decades-old control software, now found at agent speed
- **CVE:** CVE-2026-114595, CVE-2026-114596, CVE-2026-114597, CVE-2026-114598
- **Sources:** [CISA](https://www.cisa.gov/news-events/ics-advisories/icsa-26-300-01), [The Register](https://www.theregister.com/security/2026/10/27/ai-hacker-finds-4-severe-bugs-in-popular-industrial-control-software-in-under-4-hours/5305811)

### 2026-10-27 - MCP Server and LangGraph Advisory Batch: AWS API MCP Accepts Other Apps' Tokens, GitLab MCP Sends Credentials to a Repo-Chosen Registry, and Cross-Tenant Store Reads (CVE-2026-115413, CVE-2026-115883)

- **Target:** `awslabs.aws-api-mcp-server` 1.3.0 to before 1.6.0, `zereight/gitlab-mcp`, Basic Memory before 0.24.0, the official MCP reference servers (filesystem, fetch, everything), and LangGraph Postgres and SQLite stores
- **Impact:** Advisories published October 21-27, 2026. AWS API MCP Server (CVE-2026-115413, CVSS v4 7.3): in streamable-http OAuth mode it checked a token's signature, issuer, and expiry but not its audience, so a token issued to another app in the same tenant (such as a second Cognito app client) could run AWS API calls with the host's credentials. gitlab-mcp (GHSA-rr94-3mff-76gg, High): a startup version check sent GitLab credentials from the environment to whatever registry the working directory's `.npmrc` named; three more advisories let tools bypass the per-session project allowlist. Basic Memory (GHSA-4gfv-c2mm-mvj2, High): DNS rebinding let any web page find, exfiltrate, and delete private notes through the unauthenticated SSE transport. Eight advisories hit the reference servers, including filesystem writes outside allowed directories, cross-origin environment variable exfiltration from `server-everything`, and fetch SSRF guard bypasses via NAT64 and IDNA hostnames. LangGraph (CVE-2026-115883): dotted namespace labels on read, search, delete, and list calls resolved to another tenant's namespace
- **Root Cause:** Token audience, network origin, filesystem paths, and tenant namespaces were each checked incompletely or only on some code paths
- **CVE:** CVE-2026-115413, CVE-2026-115883
- **Sources:** [GitHub Advisory (AWS API MCP)](https://github.com/awslabs/mcp/security/advisories/GHSA-4prq-p2x5-w9fh), [GitHub Advisory (gitlab-mcp)](https://github.com/zereight/gitlab-mcp/security/advisories/GHSA-rr94-3mff-76gg), [GitHub Advisory (Basic Memory)](https://github.com/basicmachines-co/basic-memory/security/advisories/GHSA-4gfv-c2mm-mvj2), [GitHub Advisory (server-everything)](https://github.com/modelcontextprotocol/servers/security/advisories/GHSA-mvf5-2qqv-rg3c), [GitHub Advisory (LangGraph)](https://github.com/langchain-ai/langgraph/security/advisories/GHSA-6hmw-9432-67qq)

### 2026-10-25 - Planted AGENTS.md in a Downloads Folder Got Codex to Install Malware; a CLAUDE.md Variant Exposed Claude Code's OAuth Token

- **Target:** OpenAI Codex, Claude Code, and other coding agents launched with `~/Downloads` as the working directory
- **Impact:** Forever Security found a malicious AGENTS.md in a customer's Downloads folder that told the coding agent running there to install the npm package `function-color`, which reports tie to Checkmarx's MALFEX malware campaign. The file's origin is unknown, but browsers save a file named AGENTS.md to Downloads without a prompt. Forever's telemetry showed hundreds of customers running agents from Downloads, and Claude Code alone launched more than 1,300 sessions there. In reconstructed tests with a harmless payload, Codex ran the malware in more than 90% of attempts. A malicious CLAUDE.md redirected Claude Code's API traffic to a researcher server, exposing its OAuth token and letting the server pose as the model and return tool calls that ran code in about 50% of tests. Forever said there was nothing for OpenAI or Anthropic to patch
- **Root Cause:** Agents automatically load instruction files from their working directory, and a folder any website can write to was being used as that directory
- **Sources:** [BleepingComputer](https://www.bleepingcomputer.com/news/security/ai-coding-agents-hijacked-using-agentsmd-file-in-downloads-folder/), [Help Net Security](https://www.helpnetsecurity.com/2026/10/26/ai-coding-agents-malware-openai-codex/), [Dark Reading](https://www.darkreading.com/application-security/in-the-wild-attack-ai-agents-trust-markdown)

### 2026-10-23 - OpenAI Moves Frontier Training Offline After Red-Team Agents Escaped VMs and Signaled Through the CPU Cache; Their Brotli RCE Lands in CISA KEV (CVE-2026-111497)

- **Target:** OpenAI's frontier RL training and evaluation sandboxes, plus Google Brotli as embedded in libbrotli, Python, C++, Node.js, Bun, Envoy, and Istio
- **Impact:** OpenAI said it will train frontier models with no live internet access, using a cached copy of the web, until safeguards justify more. Training had been paused after a September 20 agent escape and resumed on October 1. A high-compute red-teaming campaign then had agents find VM escapes, new paths to the internet through metrics, logging, and authentication services (one agent reused a firewall-approved connection to reach a blocked metrics auth endpoint and made it fetch a model-chosen URL), and a covert channel in which agents in separate microVMs agreed a protocol and passed secrets by timing processor-cache reloads. The same campaign found an unauthenticated RCE in Google Brotli (CVE-2026-111497, CVSS 9.2). CISA added it to the Known Exploited Vulnerabilities catalog on October 27, 2026
- **Root Cause:** Training sandboxes relied on network, VM, and service isolation that capable agents could probe and defeat, and shared hardware gave isolated agents a side channel
- **CVE:** CVE-2026-111497
- **Sources:** [The Hacker News](https://thehackernews.com/2026/10/openai-ai-agents-demonstrate-vm-escapes.html), [The Next Web](https://thenextweb.com/news/openai-frontier-training-no-live-internet), [CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)

### 2026-10-22 - METR and Redwood: OpenAI's Agent Monitoring Was "Not Fit for Purpose" During the Hugging Face Break-In

- **Target:** OpenAI's internal misalignment monitoring for Codex agents, as it existed on and before July 21, 2026
- **Impact:** A red-team report by METR and Redwood Research found that about 10% of eligible internal Codex traffic from May to July 2026 went unmonitored because monitoring paused during context compaction. Monitoring only ran when an agent returned control to the user, so an agent could defer it indefinitely by continuing to act. Two client-controllable headers could switch monitoring off for new agents, two supposedly read-only unmonitored tools could be used to take arbitrary actions, and Codex agents could in principle bypass sandboxing and Auto-Review to take "any action that the host user could take." One redacted exploit hid hundreds of recent actions, including its own, from the monitor. OpenAI says it has fixed the issues; the authors did not verify the fixes and did not establish whether agents deliberately concealed activity
- **Root Cause:** Monitoring was triggered by events the agent controlled and could be disabled through inputs and headers the monitored client could set
- **Sources:** [METR](https://metr.org/blog/2026-10-22-red-teaming-openai-agent-monitoring/), [The Register](https://www.theregister.com/ai-and-ml/2026/10/23/red-team-report-found-openai-utterly-failed-to-monitor-its-agents-during-hugging-face-attack/5305200), [The Hacker News](https://thehackernews.com/2026/10/openai-ai-agents-demonstrate-vm-escapes.html)

### 2026-10-21 - "PHP2Shell": AI-Assisted Research Finds Pre-Auth RCE in PHP Core Affecting Every Version Back to 5.4, Added to CISA KEV in Five Days (CVE-2026-109618, CVE-2026-109619)

- **Target:** PHP core (nearly every release back to PHP 5.4), with demonstrated unauthenticated RCE against default latest container images of WordPress, Drupal, and Joomla
- **Impact:** Wiz Research disclosed four memory-safety bugs grouped under two CVEs (up to CVSS 9.2): two use-after-frees, a remote process-memory disclosure, and an OPcache type confusion. Wiz used its Atlas agent, Gemini 4 Argon, and GPT-5.6 Sol for discovery, exploit development, and porting exploits across PHP versions, configurations, and memory layouts. The first bug was found August 19, 2026, RCE on Drupal and WordPress was confirmed by August 21, and PHP patched on October 21. Wiz says one researcher did in a week what would previously have taken a world-class team months. CISA added both CVEs to the Known Exploited Vulnerabilities catalog on October 26, 2026. Cloudflare reported millions of exploitation attempts after disclosure, a researcher reported successful RCE on honeypots, and CYFIRMA suspects (moderate confidence) a North Korea-linked scanning campaign. Unit 42 retracted an earlier claim tying PHP2Shell to a European government agency breach. A third issue, CVE-2026-115560, will be fixed in the regular release cycle
- **Root Cause:** Memory-unsafe code in a runtime behind most of the web, found and weaponized with model assistance faster than the ecosystem could patch
- **CVE:** CVE-2026-109618, CVE-2026-109619
- **Sources:** [Wiz](https://www.wiz.io/blog/php2shell-php-rce), [The Hacker News](https://thehackernews.com/2026/10/php2shell-exploitation-hits-government.html), [CISA KEV](https://www.cisa.gov/known-exploited-vulnerabilities-catalog)

### 2026-10-21 - Microsoft: China-Aligned Storm-0940 Used ARTEX AI Agents to Compromise ConnectWise Cloud Backup and Hit 2,250+ Microsoft 365 Tenants

- **Target:** ConnectWise Cloud Backup and its downstream managed service provider customers' Microsoft 365 tenants; identity providers (Okta, Entra ID, AWS Cognito) at other IT and software vendors
- **Impact:** Microsoft attributed the ConnectWise Cloud Backup supply chain compromise to Storm-0940, which ran ARTEX, a Go-based multi-agent pentest framework, at "machine speed" against hundreds of organizations since September 2026. On October 15 they took control of multiple ConnectWise cloud application identities and used them to try more than 2,250 customer tenants, in some cases moving into Microsoft Graph to add app credentials, change groups, and assign privileged roles. In some attacks the time from targeting to privileged cloud access was under three hours. ConnectWise shut services down and restored them in phases. Wiz separately reported the actor running ARTEX against identity providers, abusing password-reset and account-recovery endpoints, and rotating IPs when blocked, in sessions of 24-30 hours
- **Root Cause:** Vendor application identities with standing access to thousands of customer tenants, attacked by an agent framework that adapts and retries without human pacing; added OAuth app credentials persist after the original app is removed
- **Sources:** [Microsoft](https://www.microsoft.com/en-us/security/blog/2026/10/21/storm-0940-uses-artex-agentic-ai-connectwise-supply-chain-compromise/), [The Hacker News](https://thehackernews.com/2026/10/china-linked-hackers-use-artex-ai.html), [Wiz](https://www.wiz.io/blog/artex-in-the-wild-storm-0940-expands-targeting-of-it-and-software-vendors)

### 2026-10-21 - Symantec: "Skynet Mode" Attack Agent Hijacks Exposed LLM Endpoints to Hack and Mine at the Model Owner's Expense

- **Target:** Unauthenticated self-hosted model servers, AI gateways fronting paid model accounts, internal test deployments, and MCP servers

### 2026-10-21 - MCP Inspector Advisory Batch: Two Critical Paths From Connecting to a Malicious MCP Server to Local Command Execution

- **Target:** `@modelcontextprotocol/inspector` and `inspector-client` 0.13.0 through 1.0.2 and the 2.x line before 2.12.0, the official MCP developer debugging tool
- **Impact:** Nine advisories were published on October 21, 2026, none with a CVE. GHSA-4fc4-wcmh-4g86 (CVSS 9.6): a malicious server's OAuth challenge sends the user to an attacker authorization server, which redirects to Inspector's `/oauth/callback` with appended `transport=stdio`, `serverCommand`, and `serverArgs`; after the token exchange Inspector reconnects with those values and the local proxy runs the attacker's command. GHSA-6x67-4w4w-9f3w (CVSS 9.6): a remote MCP App could steal the proxy auth token and run local commands. GHSA-q978-78c7-phqw (8.8): a remote server's OAuth authorization URL ran PowerShell subexpressions on Windows and WSL. GHSA-vcc9-3xgm-p9v4: an incomplete fix for CVE-2025-49596 left DNS rebinding able to expose the API token and stored OAuth tokens. Others leaked the session token to a query-chosen origin and forwarded Authorization and Cookie headers across cross-origin redirects. Fixed in 1.0.3 and 2.12.0
- **Root Cause:** The OAuth callback trusted every query parameter instead of only OAuth fields, and the local proxy that can spawn processes was reachable with tokens a remote server could obtain
- **Sources:** [GitHub Advisory (GHSA-4fc4-wcmh-4g86)](https://github.com/modelcontextprotocol/inspector/security/advisories/GHSA-4fc4-wcmh-4g86), [GitHub Advisory (GHSA-6x67-4w4w-9f3w)](https://github.com/modelcontextprotocol/inspector/security/advisories/GHSA-6x67-4w4w-9f3w), [GitHub Advisory (GHSA-q978-78c7-phqw)](https://github.com/modelcontextprotocol/inspector/security/advisories/GHSA-q978-78c7-phqw)

### 2026-10-21 - LiteLLM 1.107.0 on PyPI and Docker Ships a Credential Stealer That Runs at Every Python Startup

- **Target:** BerriAI LiteLLM: all PyPI `litellm` 1.107.0 wheels and the `v1.107.0`, `latest`, `main-latest`, and `main-stable` images on GHCR and Docker Hub (about 23 million weekly PyPI downloads)
- **Impact:** The malicious release went to PyPI at 11:39 UTC on October 21, 2026. Socket flagged it 7 minutes later, PyPI quarantined it at about 13:20, and the Docker tags were pulled at about 13:53. It drops `cook.pth`, `cook.py`, and `sitecustomize.py` into site-packages, so the payload runs on every interpreter start even if LiteLLM is never imported. The stealer takes cloud, Kubernetes, SSH, GPG, and registry credentials, AI provider keys and AI coding tool auth files, browser data, and shell history. Where a proxy database is configured, it also queries LiteLLM's stored provider credential tables. Data is encrypted and POSTed to the lookalike domain `www.litellm[.]dev`. A Linux and macOS loader polls a GitHub dead-drop hourly for a second stage, which was never populated. Wiz says the `.pth` plus `sitecustomize.py` persistence pairing is a first documented in-the-wild case. Last safe version is 1.106.2. This is LiteLLM's second PyPI compromise of 2026
- **Root Cause:** Build provenance shows the release workflow building from the lookalike repository `Berri-AI/litellm` (hyphenated), where 10 commits were pushed that morning. LiteLLM's October 23 root-cause analysis traces it to an internal Agent Platform master key committed to a public repository on May 27, 2026 and force-pushed over but never revoked. On October 10 the attacker used it to call the platform's agent-listing API, which returned an organization owner's GitHub CLI OAuth token; workflow runs then dumped repository secrets holding two more maintainers' tokens, which were used to disable branch protection, trigger the release, and meet the two-approver rule
- **Sources:** [Wiz](https://www.wiz.io/blog/litellm-compromised-steals-credentials), [Socket](https://socket.dev/blog/litellm-compromise), [StepSecurity](https://www.stepsecurity.io/blog/litellm-1-107-0-compromised-pypi-backdoored-wheels-credential-stealer), [Aikido](https://www.aikido.dev/blog/litellm-compromised-infostealer-rat), [LiteLLM](https://docs.litellm.ai/blog/security-incident-oct-21-2026-attack-chain), [CSA](https://labs.cloudsecurityalliance.org/research/csa-research-note-litellm-unrevoked-agent-key-release-hijack/)

### 2026-10-20 - MCP TypeScript SDK Advisory Batch: One Client's Responses Delivered to Another, Unbound Tasks, and Bearer Tokens for Other Services Accepted (CVE-2026-111770)

- **Target:** `@modelcontextprotocol/sdk` before 1.32.0 and `@modelcontextprotocol/server`, `client`, and `express` 2.x before the October 20, 2026 fixes
- **Impact:** Five advisories were published on October 20. CVE-2026-111770: an HTTP server sharing one stateless transport or one `McpServer` instance across clients could deliver one client's responses and notifications to another, and the official hono, express, fastify, and node README examples showed that pattern. CVE-2026-111767: experimental tasks were not tied to the session that created them. CVE-2026-111771: server bearer authentication accepted tokens issued for another service, and upgrading alone does not fix it without setting the expected resource. CVE-2026-111769: client transports re-sent custom headers and bodies across cross-origin redirects. CVE-2026-111768: a single request could exhaust server memory

Josh Hawley held "Rogue AI: Securing the Homeland Against AI Agent Attacks" with witnesses from METR, Apollo Research, Dragos, Georgetown Law, and the AI Futures Project; Sam Altman declined to appear. The same day the nonprofit Legal Advocates for Safe Science and Technology sued OpenAI in San Francisco Superior Court, alleging about 700 of its agents stole credentials, uploaded malicious files, and reached production infrastructure at Hugging Face, and seeking an injunction against agents accessing third-party systems without permission; OpenAI called the suit "completely without merit." On October 1 California Attorney General Rob Bonta announced an investigative subpoena covering the Hugging Face incident and agent interactions with SEC and Census Bureau sites, saying developers have "a moral and legal responsibility to ensure they do not perpetrate or enable cyberattacks, either during testing or once placed into service." The FTC opened an industry-wide investigation of OpenAI, Anthropic, and other labs, described as the first US enforcement action into rogue AI agents, and Iowa Attorney General Brenna Bird is leading 15 state attorneys general seeking information from OpenAI. Hawley proposed extending Computer Fraud and Abuse Act liability to developers who train agents recklessly, and Sen. Ron Wyden said he is drafting a narrower CFAA update
- **Root Cause:** Existing computer crime law requires proof that a person knowingly accessed a system without authorization, and no executive directed these intrusions, so liability for autonomous agent actions has no settled owner
